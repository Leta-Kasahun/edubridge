# EduBridge Phase 2 — Complete Implementation Plan
## Competency-Based Assessment Engine

### Background

Phase 1 (Curriculum + Learning Content) is complete and stable. The Prisma schema already
contains every Phase 2 model. This plan covers the **backend module code, shared utils/constants,
and frontend scaffolds** that bring those models to life.

The **exam-prep module stub is being removed** — exam-preparation flows through the standard
Question Bank → Assessment → Attempt → Grading → Evidence → Mastery pipeline, differentiated
only by `ExamContext` data, not a separate architecture.

---

## User Review Required

> [!IMPORTANT]
> **Exam-prep module removal** — `apps/api/src/modules/exam-prep/` contains only empty stub
> files. The plan deletes it and routes all exam-context logic through the new `question-bank`
> and `assessment` modules. Confirm before execution.

> [!IMPORTANT]
> **Question ingestion change** — The primary question-bank entry path is now **manual authoring
> + image/PDF upload with teacher review**, not a CSV/XLSX import. The import path is
> **removed entirely** from this feature. Confirm you want it removed, not just hidden.

> [!WARNING]
> **No new Prisma migrations needed** — the schema already defines every Phase 2 model.
> All implementation work is code only (services, controllers, routes, shared utils/constants,
> and frontend). If you want schema additions (e.g., `sourceFileKey` on `QuestionVersion` for
> tracing uploaded PDFs), say so before execution and a migration will be added.

---

## Open Questions

> [!IMPORTANT]
> 1. **PDF/Image extraction** — Should the upload step attempt AI-assisted OCR/parsing of
>    questions from the file, or simply store the file so the teacher uses it as a visual
>    reference while manually typing each question?
> 2. **Time-limit enforcement** — Server-side attempt expiry (server stamps `EXPIRED`) or
>    client-side countdown + submission enforcement only?
> 3. **SHORT_ANSWER grading** — Auto-grade by keyword matching, or always route to manual
>    grading in Phase 2?

#### Upload → Review → Create Flow (replaces question-bank import)

1. Teacher uploads a PDF or image via multipart.
2. Service validates (type, size, tenant), stores file to `uploads/question-sources/{tenantId}/`, returns transient `uploadId` in Redis.
3. Service extracts raw text blocks from the file (Phase 2: text extraction only; Phase 3 extension point: LLM parsing injected here without model change).
4. Teacher sees parsed blocks, edits each one — assigns question type, difficulty, options, correct answer, topic mapping.
5. Teacher confirms; service creates `Question` + `QuestionVersion` records transactionally (status = `DRAFT`).
6. Teacher submits for review/publish through the standard question lifecycle.

> [!NOTE]
> The confirm step is identical whether questions came from upload or manual authoring —
> this is the Phase 3 AI extension point with no data model change required.

`evidence.service.ts` is called by the grading pipeline after each attempt is graded:

1. For each graded `StudentAnswer`, create one `LearningEvidence` record per linked `QuestionTopic` and `QuestionObjective`.
2. Atomically upsert `StudentTopicPerformance` aggregates (`increment` correct/incorrect/points counts).
3. Trigger `MasteryService.recalculate()` for each affected topic.

**`MasteryService.recalculate(studentId, topicId, tenantId)`:**

1. Load `StudentTopicPerformance` (correctCount, questionCount).
2. Compute accuracy with `computeAccuracy()`.
3. Map to `MasteryLevel` with `computeMasteryLevel()`.
4. Upsert `StudentTopicMastery`.
5. Append `MasteryHistory` record.

Before listing what to add, here is the established pattern every Phase 2 feature must follow:

```
features/<domain>/
├── <sub-domain>/
│   ├── components/     ← UI components for this sub-domain
│   ├── hooks/          ← TanStack Query hooks (useXxx.ts)
│   ├── services/       ← API calls (xxx.service.ts)
│   ├── types/          ← TypeScript types (xxx.types.ts)
│   └── index.ts        ← barrel re-exports
├── components/         ← Shared components used across sub-domains
└── index.ts            ← Root barrel re-exports for the whole feature
```
